# Ryoku port — translated configuration

The SwayFX desktop cannot be copied into Ryoku: Ryoku's shell (bar, launcher,
Hub, lockscreen, greeter) is the desktop, and the compositor underneath is
Hyprland or niri. These files are the keybinding layer of the old setup,
translated.

**Neither file has been tested on Ryoku.** They are a starting point built
from the captured Sway configuration; check every action name against the
versions Ryoku ships before relying on them.

| File | Target | Install to |
|---|---|---|
| `hypr/user.lua` | Hyprland | `~/.config/hypr/user.lua` |
| `niri/user.kdl` | niri | `~/.config/niri/user.kdl` |

Ryoku's own layout, per the upstream documentation:

- **Hyprland** — `~/.config/hypr/` holds `hyprland.lua` (the authored entry),
  `settings.lua` and `rebinds.lua` (both generated by the Hub) and the seeded
  `monitors.lua`, `gpu.lua`, `keyboard.lua` and `user.lua`. The personal
  override layer is `user.lua`.
- **niri** — `~/.config/niri/` holds `config.kdl` (the entry, which includes
  the rest), `settings.kdl` and `rebinds.kdl` (generated) and the seeded
  `monitors.kdl`, `monitors_user.kdl`, `gpu.kdl`, `keyboard.kdl` and
  `user.kdl`. **The last include wins**, so `user.kdl` is the override layer.
  niri has no unbind: a duplicate chord is a hard error, and every file named
  in `config.kdl` must exist or the session does not start.

## What was deliberately not translated

- **`$mod+d` (Fuzzel) and the nwggrid drawer.** Ryoku's launcher is the
  single search surface: apps, commands, files, packages, radio and a
  calculator. Super opens it.
- **`$mod+Shift+v` (CopyQ) and `$mod+Shift+s` / `$mod+Shift+w` (Sway Control
  Center).** Ryoku's Hub (`Super+,`) and its clipboard replace them. The
  control center's appearance panel is superseded by the Ryoku Hub, which
  drives the same GTK/Qt/Kvantum/Flatpak backends.
- **`$mod+Pause` (passthrough mode).** Hyprland has submaps, niri has no
  equivalent; Ryoku's own binds cover the media keys.
- **The XF86 media, volume and brightness keys.** Ryoku owns them through
  PipeWire/WirePlumber and the Hub.
- **The SwayFX five-colour client palette.** Ryoku's `paletteBorder` capability
  keeps the border tied to the wallpaper, which is the same intent as the
  SwayFX `client.*` colours. Set it in the Hub rather than in `user.lua`.

## The rest of the desktop

The appearance stack transfers unchanged, because it is plain GTK/Qt/XSettings
configuration:

```bash
cp -a backup/home/config/gtk-3.0  backup/home/config/gtk-4.0  ~/.config/
cp -a backup/home/config/qt5ct    backup/home/config/qt6ct        ~/.config/
cp -a backup/home/config/Kvantum                                        ~/.config/
cp -a backup/home/config/xsettingsd                                     ~/.config/
tar --zstd -xf backup/archives/fonts.tar.zst -C ~/.local/share
flatpak override --user --filesystem=/usr/share/icons/Bibata-Modern-Ice:ro \
                        --filesystem=/usr/share/icons/Yaru-prussiangreen-dark:ro
flatpak override --user --env=XCURSOR_THEME=Bibata-Modern-Ice --env=XCURSOR_SIZE=24
```

The panel is `eDP-1` at 1920x1080 and 144 Hz, and **adaptive sync stays off**
(the same pointer-movement flicker that made it visible in Sway applies here):

- Hyprland: `~/.config/hypr/monitors.lua` (seeded, machine-owned)
- niri: `~/.config/niri/monitors.kdl` and `monitors_user.kdl`

## NVIDIA

The current Fedora install runs the proprietary driver with nouveau
blacklisted. **Ryoku's Fedora edition leaves NVIDIA on nouveau.** Pick one
before the install:

- proprietary → verify the Ryoku compositor works with it, keep
  `/etc/modprobe.d/blacklist-nouveau.conf` and `nvidia-drm.conf`, and rebuild
  the initramfs after every kernel update (the dracut helper in this backup
  is Fedora-specific; on Arch the equivalent is `mkinitcpio -P` with the
  NVIDIA modules included);
- nouveau → drop the blacklist and the `--unsupported-gpu` flag; they are
  meaningless there.
